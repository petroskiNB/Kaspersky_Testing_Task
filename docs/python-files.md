# Python-файлы проекта

## app/__init__.py

Обозначает каталог `app` как Python-пакет. При импорте выполняется только
строка документации; сервер и эндпоинты здесь не создаются. Благодаря пакету
vLLM может импортировать класс по имени
`app.request_logging.RequestMetadataMiddleware`.

## app/request_logging.py

Это middleware — обёртка вокруг существующего ASGI-приложения vLLM.
Собственные эндпоинты не нужны: их предоставляет vLLM.

### Импорты и константы

- `json` сериализует метаданные в одну JSON-строку.
- `logging` передаёт строку логгеру `llm.requests`.
- `time.perf_counter()` измеряет длительность монотонными часами.
- `uuid.uuid4()` создаёт собственный ID запроса, без копирования ввода клиента.
- `SAFE_PATHS` и `SAFE_METHODS` содержат разрешённые значения для логов.
  Произвольный путь заменяется на `other`, метод — на `OTHER`: текст пользователя
  может попасть не только в JSON-тело, но и в адрес запроса.

### RequestMetadataMiddleware.__init__

Сохраняет приложение в `self.app`. vLLM создаёт middleware через свой параметр
`--middleware`. Дополнительные Python-зависимости не требуются.

### RequestMetadataMiddleware.__call__

Асинхронная точка входа принимает три аргумента ASGI:

- `scope` — тип соединения, метод, путь и прочие сведения;
- `receive` — функция получения входящих событий;
- `send` — функция отправки исходящих событий.

Не-HTTP события, например запуск/остановка приложения, передаются без изменений.
Для HTTP сохраняются время начала, ID и исходные признаки состояния.
Значение статуса 500 используется как запасное, если приложение упадёт до
начала ответа.

### send_with_metadata

Вложенная функция оборачивает `send`. `nonlocal` позволяет менять переменные
внешнего вызова `__call__`.

При `http.response.start` сохраняет HTTP-статус и добавляет `X-Request-ID`.
Все события, включая байты тела, передаются исходному `send`. Содержимое
тела не анализируется и не буферизуется. После последнего события
`http.response.body` отмечается `completed=true`.

Так сохраняется streaming: лог формируется после последнего блока, а не
после получения заголовков. Поле `duration_ms` — длительность обработки
до передачи последнего блока ASGI-серверу, а не TTFT.

### try / except / finally

`await self.app(...)` запускает приложение. Исключения и отмена запроса
отмечаются `failed=true` и передаются дальше через `raise`. Их текст и traceback
middleware не записывает. `finally` формирует метаданные и при успехе, и при сбое.

HTTP 400 — нормальный ответ приложения, поэтому у него может быть `failed=false`.
`failed` означает исключение, а не любой неуспешный HTTP-статус.

`completed=true` означает завершение отправки на уровне ASGI. Это не доказательство,
что удалённый клиент получил или прочитал все байты.

### Какие данные не логируются

Middleware не читает `receive`, тело ответа, заголовки запроса, query string,
тексты исключений или пользовательские ID. Конфигурация `config/logging.json`
оставляет вывод только для логгера метаданных; обычные Python-логи подавлены.
Нативный C/C++ код может отдельно писать предупреждения в stderr, поэтому
приватность проверяется также на реальном контейнере.

## tests/test_request_logging.py

Тесты используют стандартный `unittest`. Реальная модель, Docker и vLLM им
не нужны. Вместо приложения создаётся небольшая ASGI-функция, которая читает
фиктивный запрос и отправляет фиктивный потоковый ответ либо выбрасывает ошибку.
Логгер пишет в `StringIO`, чтобы можно было проверить содержимое в памяти.

`run_coroutine` исполняет тестовую корутину без event loop: все фиктивные
операции завершаются сразу, реального ввода-вывода нет. При появлении настоящего
асинхронного I/O этот помощник нужно заменить обычным асинхронным тестовым runner.

Три проверки:

1. Потоковый ответ передаётся без изменения тела; сохраняются статус и ID,
   а приватные маркеры не появляются в логе.
2. Произвольный путь заменяется на `other`.
3. Текст исключения не логируется, ошибка отмечается метаданными и передаётся дальше.

Это изолированные проверки middleware. PowerShell-скрипт
`scripts/Test-LoggingPrivacy.ps1` выполняет отдельную интеграционную проверку
всего контейнера. Пользователь успешно выполнил её для обычного запроса,
streaming и HTTP 400: метаданные присутствовали, утечки маркеров/ответов не обнаружены.

## downloader/__init__.py

Делает каталог загрузчика импортируемым пакетом, чтобы тесты могли импортировать
функции. В контейнере скрипт запускается напрямую.

## downloader/download_model.py

Одноразовая подготовка PVC, а не постоянный процесс. `main()` читает MODEL_ID,
MODEL_REVISION (полный SHA коммита) и MODEL_DIR. При ошибке пишет фиксированное
событие без токена/текста исключения и завершает процесс с кодом 1.

`prepare_model()` проверяет конфигурацию и берёт файловую блокировку, чтобы
два загрузчика не меняли модель одновременно. Затем проверяет локальный
`.model-ready.json`: идентичность модели/ревизии, размеры файлов и SHA-256.
Успешная проверка завершает скрипт без импорта клиента Hugging Face и без сети.
Смена ревизии требует отдельной папки, чтобы не смешивать разные снимки.

При отсутствии готовой модели `snapshot_download()` скачивает JSON, safetensors,
TXT и LICENSE в MODEL_DIR. HF_TOKEN читается только из окружения. При повреждении
существующих файлов они удаляются по списку манифеста перед повторной загрузкой,
чтобы локальный HF-кеш не принял повреждённые файлы за готовые.

После загрузки проверяются JSON-файлы, наличие весов и перечисленных в индексе
шардов. Для файлов считается SHA-256 и формируется маркер. Запись через временный
файл и `replace()` не позволяет принять незавершённый маркер за готовый.
Прерванная загрузка не создаёт маркер, следующий запуск повторит подготовку.
Это контроль неизменности скачанных файлов, а не доказательство корректности
ответов модели: реальная загрузка в vLLM проверяется отдельно.

`sha256_file()` читает веса блоками по 8 МиБ, не загружая целиком в RAM.
`valid_snapshot()` выполняет локальную проверку. `emit()` выводит только
фиксированные события загрузчика.

## tests/test_download_model.py

Четыре теста с маленькими фиктивными файлами и подменённой функцией скачивания:
первая загрузка/повтор без сети, прерывание/повтор, повреждение файла при
сохранении размера и отказ от повторного использования другой ревизии.
Интернет и настоящие веса для этих тестов не требуются.

## Запуск проверок

Из корня проекта:

```powershell
python -B -m unittest discover -s tests -v
```
